在 `/mnt/data/projects/kernelet` 工作，使用当前 `poc/` 实现。目标是在可复现、对称的条件下比较虚拟机内 Linux（L）与完整 Asterinas-on-Linux（K）的 `getpid` 延迟，核实已有差距是否仍然存在。先完成实验准备和基线，优化候选保留在讨论阶段。

## 实施与测量

1. 核对当前源码和构建入口，列出第 6.3 节测量要求中已满足与缺失的条件。沿用现有构建环境；把必要的可复用测量工具放在 `poc/linux/bench/`。本任务允许补齐测试端的绑核、对称套件选择、多窗口记录和结果采集，内核热路径与功能语义保持当前版本。
2. 建立同一 Linux 构建下的 L/K 对照：L 运行普通 Linux 用户进程；K 运行完整 Kernelet POSIX 路径。两组使用同一个直接执行 `syscall` 指令的 C 基准，并按计划核实宿主 vCPU 线程、guest carrier 和 tenant 测试线程的 CPU 对应关系。测试数据与用于核对 CPU/路径的诊断数据分别保存。
3. 按计划第 6.3 节实现预热、整段计时、多窗口采样、独立启动与打乱顺序，保存随机种子、每个窗口、每次启动的原始日志和统计。计时窗口内运行单个测量，避免同时构建、启动其他实验或运行优化搜索。
4. 冻结和归档两个仓库的实际源码状态、构建配置、工具链、QEMU 命令、启动参数、CPU 放置及产物摘要。清理完成后的新构建单独标识，旧报告的数据继续保留原来的来源，现存二进制的新 hash 不作为旧实验的来源证明。
5. 运行与测试工具改动相称的构建和检查，核对返回 PID、窗口数量、CPU 记录、退出状态和 host 错误。实验缺少能力或失败时保留真实日志和原因；条件不对称的运行不进入主比较表。

临时构建、验证和中间文件使用有明确任务名的系统临时目录，结束后检查并清理。本次可复现结果归档到 `research/user-page-table/results/syscall-<run-id>/`，至少包括来源清单、执行命令、原始日志、统计表和 `report.md`。

## 审阅与完成条件

审阅者只读检查源码与原始数据，可独立重算统计，将修改与重测要求交回执行者；审阅期间不启动 QEMU 或修改实验实现。按以上来源核对实际文件、原始日志、统计和报告，检查实验是否满足第 6.3 节。正常完成需要 L/K 各至少五次独立启动、规定的窗口数据、可核对的来源和产物，以及准确描述测量条件与限制的报告；均值、跨启动中位数与单次调用延迟分位数分别表述。

原生 Asterinas（A）与最小处理器（S）留作后续独立任务，报告其当前状态和实现缺口。L/K 结果只回答整套部署差距，不能把差值归因到 `Context`、panic、FPU 或某条检查。优化候选的实现需要沿用计划中的逐项讨论与验收条件；不能用最小处理器代替完整 K，也不能删除功能检查以改善数字。
